# @kopi/desktop

Kopi's desktop app: a Tauri 2 shell in `src-tauri/` and a React and TypeScript UI in `src/`, built with Vite. The Rust core lives in [`crates/`](../../crates) and doesn't depend on Tauri. See [docs/ARCHITECTURE.md](../../docs/ARCHITECTURE.md).

It has:

- a menu bar icon and menu, and no Dock icon
- clipboard capture on macOS, through the privacy filter and the classifier into the store
- the panel: ⇧⌘V opens it over the app you're in, with the history, search, filters, preview, pinboards and pasting
- the Settings and first-run setup windows
- updates through the Tauri updater ([docs/RELEASING.md](../../docs/RELEASING.md#updates))
- the `single-instance` plugin (a second launch opens the panel) and the `autostart` plugin
- TypeScript bindings generated from the Rust commands and events

## Setup

You need the root setup from [CONTRIBUTING.md](../../CONTRIBUTING.md), plus:

- Rust from [rustup](https://rustup.rs), with `rustup component add clippy rustfmt`
- the Xcode Command Line Tools: `xcode-select --install`

You don't need to install the Tauri CLI. It's a dev dependency.

## Run and build

From the repository root:

```sh
pnpm dev:desktop      # Vite on port 1420, plus a debug build of the app
pnpm build:desktop    # target/release/bundle/macos/Kopi.app, signed ad hoc
```

Quit an installed Kopi first. It has the same identifier, so a development build finds it, hands over to it and quits.

Kopi starts in the menu bar, with no window. Press ⇧⌘V, or click the menu bar icon and choose **Open Kopi**. Copies made while it runs are captured into `~/Library/Application Support/in.devanshuverma.kopi`.

A development build checks for updates only from **Check for Updates…**, and says what it found without installing it.

## Working on the panel in a browser

`pnpm --filter @kopi/desktop dev:ui` runs only the UI, at http://localhost:1420. Outside Tauri it gets a fake backend with sample clips ([`src/dev/mockBackend.ts`](src/dev/mockBackend.ts)), so the panel can be worked on in any browser. Production builds leave it out. URL parameters set up a state to look at: `?q=invoice`, `?empty`, `?select=3`, `?theme=dark` and `?preview=closed`. Images don't load there, since the `kopi://` protocol is the app's.

Ad-hoc signed builds get a new signature on every build. Permissions that macOS ties to the signature, such as Accessibility, have to be granted again after each rebuild.

## Typed commands

Commands are Rust functions marked `#[tauri::command]` and `#[specta::specta]`, registered in `specta_builder()` in [`src-tauri/src/lib.rs`](src-tauri/src/lib.rs). [`tauri-specta`](https://github.com/specta-rs/tauri-specta) generates [`src/lib/bindings.ts`](src/lib/bindings.ts) from them. Don't edit that file by hand.

- The file is regenerated by `pnpm dev:desktop` and by `cargo test -p kopi-desktop`. Commit the result. CI fails if it's out of date.
- The UI imports commands from [`src/lib/ipc.ts`](src/lib/ipc.ts), never from `@tauri-apps/api/core`.
- A command that returns `Result<T, E>` resolves to `{ status: "ok", data }` or `{ status: "error", error }`. Use `unwrap()` from `ipc.ts` to get the data or throw.

## Checks

The same checks as CI, from the repository root:

```sh
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
pnpm --filter @kopi/desktop lint
pnpm --filter @kopi/desktop test
```
