# Privacy design

A clipboard manager sees passwords, tokens, addresses and private messages. Kopi's privacy rules are part of the design, not settings bolted on later. This document is the reference for how the app handles that data. Platform details and sources are in [PLATFORM_NOTES.md](PLATFORM_NOTES.md).

## Principles

1. **Don't read what we won't keep.** Wherever possible, decisions are made from the format list and the source app *before* any content is read. The few rules that need the content are checked in memory, and failing content is discarded without being stored or logged.
2. **Local only by default.** History never leaves the device unless the user turns on sync, and then only to the computers they pair, encrypted end to end.
3. **No telemetry.** The app sends no analytics. Any crash reporting will be opt-in and will never include clip content.
4. **The user stays in control.** Pause, exclude apps, delete clips, clear everything, and set limits.
5. **Verifiable.** The code is open, so anyone can check that these rules hold.

## What is never stored

Content is dropped when any of these is true. The first four rules are checked **before anything is read**. The last two can need a read, because the size and some kinds (link, code, color) are only known from the content. In those cases the content is read into memory, checked, and thrown away without being stored or logged.

| Rule | macOS | Windows |
| --- | --- | --- |
| Marked concealed (passwords) | `org.nspasteboard.ConcealedType`, `com.agilebits.onepassword`, `net.antelle.keeweb` | `ExcludeClipboardContentFromMonitorProcessing` present |
| Marked transient or auto-generated | `org.nspasteboard.TransientType`, `org.nspasteboard.AutoGeneratedType`, `de.petermaurer.TransientPasteboardType`, `com.typeit4me.clipping`, `Pasteboard generator type` | `CanIncludeInClipboardHistory` = 0 (the value needs a read, so this rule waits for the Windows watcher) |
| Copied from an excluded app | Source app's bundle ID is in `excluded_apps` | Source exe path is in `excluded_apps` |
| Capture is paused | Pause from the tray or the panel, with an optional "resume in 5 min / 1 h" | Same |
| Kind turned off in Settings | For example, "don't capture images". Skipped before the read when the format list rules out every kind still on, otherwise dropped after it | Same |
| Over the size limit | `limits.max_clip_bytes`, default 50 MiB | Same |

Default excluded apps on macOS: Keychain Access, Passwords, 1Password, Bitwarden, KeePassXC, Dashlane and Enpass. Most of these already set the concealed marker. The exclusion is a second layer of protection, and the user can remove any default. They're seeded once, by a migration, so a removed default isn't added back.

| App | Bundle IDs | Checked against |
| --- | --- | --- |
| Keychain Access | `com.apple.keychainaccess` | The installed app (macOS 27) |
| Passwords | `com.apple.Passwords` | The installed app (macOS 27) |
| 1Password | `com.1password.1password` (8), `com.agilebits.onepassword7` (7) | Fleet and Kandji app catalogs |
| Bitwarden | `com.bitwarden.desktop` | Code-signing requirement (team LTZ2PFU5D6) |
| KeePassXC | `org.keepassxc.keepassxc` | Code-signing requirement (team G2S7P7J672) |
| Dashlane | `com.dashlane.Dashlane`, `com.dashlane.dashlanephonefinal` (App Store) | Info.plist listings |
| Enpass | `in.sinew.Enpass-Desktop`, `in.sinew.Enpass-Desktop.App` | Crash logs on the Enpass forum |

Bundle IDs are matched without regard to case, as macOS does. Windows defaults come with the Windows port.

A dropped copy leaves no trace: no row, no file and no log line with content. A counter of skipped copies may be shown ("3 sensitive copies skipped today"), so the user knows the filter works.

### Limits of what we can detect

- If a password manager doesn't mark its copies, and the user hasn't excluded it, the copy is captured like any other. Onboarding says this plainly, and the panel makes it easy to delete one clip or exclude the app it came from.
- The source app is a best guess on both platforms (see PLATFORM_NOTES), so an exclusion can miss a copy made by a background helper of an excluded app.
- Pattern-based secret detection (API keys, card numbers) isn't in the alpha. It's a candidate for later, as an opt-in that hides or skips matches.

## Local only by default

- **Where data lives:** the database and files are in the local, non-roaming app data folder ([DATA_MODEL.md](DATA_MODEL.md#storage-location)), created with user-only permissions.
- **Network:** apart from sync, which is off until the user turns it on, Kopi's only network requests are the updater's. Every few hours it fetches `latest.json` from the project's GitHub releases, and the update itself when there's one. They send no clip data, no settings and no ID, only what any download sends (an IP address and a user agent). **Update automatically** in Settings turns the automatic checks off, leaving **Check for Updates…** in the menu bar. See [RELEASING.md](RELEASING.md#updates). The webview's content security policy (`connect-src`) allows no remote hosts, and the app doesn't include Tauri's HTTP plugin.
- **Webview isolation:** the UI has no direct clipboard, file system or SQL access. It can only call Kopi's own commands (see [ARCHITECTURE.md](ARCHITECTURE.md)). The content security policy blocks remote scripts.
- **Encryption at rest:** the alpha relies on FileVault / BitLocker. Encrypting the database (for example with SQLCipher and a key in the Keychain / Credential Manager) is an open question for the beta. It protects against other local processes reading the file, at a cost to complexity and speed.
- **Screen sharing:** Concealed content is never stored, so it can't be shown in the panel. A "hide previews while screen sharing" option is a later idea.

## History limits

Unlimited history is the default, because it's what users ask for. Limits are easy to set:

- By count (for example, keep 1,000 clips)
- By age (1, 7, 30, 90 or 365 days)
- By total size (default 2 GiB)

Pinned clips and clips on pinboards are exempt from limits. Lowering a limit applies straight away. Details are in [DATA_MODEL.md](DATA_MODEL.md#retention-and-cleanup).

## Deleting and clearing history

| Action | Effect |
| --- | --- |
| Delete a clip | Removes the row, its formats, its FTS index entries and any files no longer referenced |
| Clear history | Deletes all unpinned clips, with a checkbox to include pinned clips and pinboards. Then runs `VACUUM` and a WAL checkpoint, so nothing lingers in free pages or the WAL file. |
| Clear the last hour or day | Quick options next to Clear history in Settings, for "I just copied something I shouldn't have" |
| Uninstall | The app data folder is documented, so it can be removed. On Windows the uninstaller offers to remove it. |

SQLite is set up to overwrite deleted content: `PRAGMA secure_delete = ON` for tables, and the FTS5 `secure-delete` option for the search index. A copy of the content can still exist in backups (Time Machine, File History) and in SSD-level remapping. The settings page says so honestly rather than promising "secure erase".

## Permissions, explained to the user

| Permission (macOS) | What Kopi does with it | Without it |
| --- | --- | --- |
| Paste from Other Apps | Reads the clipboard in the background to build history | Kopi can't build history (macOS 27.2+, see PLATFORM_NOTES) |
| Accessibility | Sends ⌘V to paste into the app you were using | Kopi copies the clip, and you press ⌘V yourself |

Onboarding asks for each permission with a one-sentence reason and a link to this document. The Paste from Other Apps step only appears on macOS versions that enforce it. On older versions there's nothing to grant, so the step is skipped. Kopi asks for nothing else.

## Sync

Settings → Sync syncs history, pins and pinboards between the user's own computers. The design is in [SYNC_DESIGN.md](SYNC_DESIGN.md) ([ADR 0007](decisions/0007-lan-sync.md)).

- **Off by default.** While it's off, Kopi opens no socket and advertises nothing.
- **Local network only, no server.** Clips go straight from one paired computer to another, **end-to-end encrypted** (Noise, with keys pinned at pairing). The keys never leave the computer: each is in `<data dir>/sync/device.key`, readable only by the user.
- **Only computers the user pairs**, one at a time, with a 6-digit code shown on screen. A wrong code fails, and the code changes after every attempt.
- **What others on the network see:** while sync is on, a computer advertises a Kopi service under a random name that changes every time sync starts. Anyone who connects can learn its public key, which is a stable identifier, but nothing else: a computer that isn't paired is refused before anything is sent.
- **Never synced:** file clips, copies Windows marks with `CanUploadToCloudClipboard` = 0, and kinds the user unticks in **What to sync**. Concealed and transient copies are never stored, so they can't sync.
- **Excluded apps** on the receiving computer apply to clips copied on a computer of the same OS: a clip from an app it excludes is dropped on arrival.
- **Deletes and Clear history reach every computer** in the group.
- **Received data is untrusted**, even from a paired computer: sizes are limited, fields are checked, and each clip's hash is recomputed from its content.
- **Removing a computer** stops every computer in the group accepting it. It keeps what it already received; Kopi can't reach into another computer.
- **Logs** have device IDs, counts and errors, never clip content.

macOS asks for the Local Network permission when sync is first turned on, and Windows Defender Firewall asks to allow Kopi. See [INSTALL_ALPHA.md](INSTALL_ALPHA.md#sync).
